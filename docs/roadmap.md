# PurpJob — Roadmap разработки MVP

> Роадмап **продуктовых модулей**, а не технический. Технологии (API/local LLM, pgvector, FastAPI,
> Chrome Extension) в мастер-документе намеренно оставлены как карта вариантов, а не решения.
> Сначала определяется поведение продукта, затем техническая реализация.

## Модуль 1. Регистрация и базовый профиль кандидата

1. Как кандидат, я хочу создать профиль PurpJob, чтобы иметь единое место для хранения и накопления своей профессиональной репутации.
2. Как кандидат, я хочу импортировать существующее резюме и/или основные данные о своём опыте, чтобы не заполнять профиль с нуля.
3. Как кандидат, я хочу видеть, какие данные и источники используются для формирования моего профиля, чтобы контролировать информацию о себе.
4. Как кандидат, я хочу самостоятельно редактировать, подтверждать или отклонять данные профиля, чтобы PurpJob не приписывал мне опыт, которого у меня не было.

**Результат:** не «резюме», а базовый накопительный профессиональный профиль.

## Модуль 2. One-Click Enrichment и Evidence

1. Добавить ссылки на доступные профессиональные источники и артефакты, чтобы усилить профиль реальными доказательствами опыта.
2. Загрузить описание проекта или кейса в свободной форме, чтобы система сама структурировала его в компетенции и результаты.
3. Видеть, какое утверждение профиля подтверждается каким Evidence.
4. Отказаться от раскрытия конкретного источника или факта (конфиденциальность), не теряя возможности подтвердить компетенцию другим способом.

**Результат:** профиль состоит не только из деклараций, но и из Evidence.

## Модуль 3. PROF.индекс

1. Получить структурированный PROF.индекс компетенций вместо длинного текста резюме.
2. Видеть, какие компетенции подтверждены сильными Evidence, а какие имеют недостаточную доказательную базу.
3. Видеть «белые пятна» профиля.
4. Получить Self-Audit — для оценки собственного профессионального развития, не только для поиска работы.

Эталонная библиотека PROF первого сегмента: **Backend/Fullstack, Python/Go, Middle/Senior**.

## Модуль 4. Contextual Probe

1. Отвечать только на вопросы по недостаточно подтверждённым компетенциям, а не проходить общий тест.
2. Получать вопросы на основании профиля, Evidence и «белых пятен».
3. Отвечать в свободной форме, объясняя логику решений, а не угадывая вариант.
4. Видеть, какую компетенцию проверял каждый вопрос и почему он задан.
5. Отказаться от ответа или указать NDA-ограничение.

**Результат:** система точечно закрывает пробелы в доказательной базе.

## Модуль 5. NDA / альтернативная верификация

1. Подтвердить опыт под NDA без раскрытия клиента, кода и коммерческих деталей.
2. Пройти Mirror Task — аналогичную, но новую задачу.
3. Использовать Метод Слепого Свидетеля.
4. Отклонить предложенный способ подтверждения и выбрать другой допустимый.

**Результат:** отсутствие публичного Digital Footprint не означает невозможность создать Trust.

## Модуль 6. Trust Score

1. Получить Trust Score, отражающий степень подтверждённости профиля.
2. Понимать, какие независимые подтверждения на него повлияли.
3. Видеть, какие действия усилят доверие к конкретным частям профиля.
4. Оспорить ошибочное утверждение, повлиявшее на Trust Score.
5. Слабое подтверждение не должно превращаться в «штраф» — только в необходимость дополнительной проверки.

Trust Score **не заменяет** GitHub, портфолио, рекомендации или интервью — он агрегирует источники и добавляет контекстную проверку.

## Модуль 7. XAI и модерация

1. Понимать, почему система сделала конкретный вывод о PROF или Trust.
2. Видеть конкретные Evidence в основании вывода.
3. Оспорить результат и передать случай на ручную модерацию.
4. Как модератор — просматривать спорные случаи и корректировать ошибочные выводы.
5. Как система — хранить историю изменения спорного результата.

**Принцип:** AI предлагает вывод, но не становится неоспоримым судьёй кандидата.

## Модуль 8. Накопительный профиль и Logic over Memory

1. Подтверждённый опыт сохраняется после завершения конкретного поиска работы.
2. Пройденная проверка переиспользуется, если релевантна другой вакансии.
3. Новые вопросы — только там, где предыдущих доказательств недостаточно.
4. Видна история усиления профиля во времени.

**Критическая часть продукта:** результат проверки становится активом кандидата, а не исчезает после закрытия вакансии.

## Модуль 9. Экспорт профессионального профиля

1. Экспорт профиля в привычном формате.
2. PDF-резюме, автоматически сформированное из профиля.
3. Trust Score в экспорте вместе с краткой статической легендой.
4. Кандидат отправляет профиль сам — платформа не рассылает от его имени.

## Модуль 10. Вакансии и базовый Match

1. Видеть релевантные вакансии — повод пользоваться PurpJob до появления recruiter-side рынка.
2. Видеть соответствие профиля вакансии.
3. Понимать, какие требования подтверждены, а какие остаются белыми пятнами.
4. Получить рекомендацию, что усилить под конкретную вакансию.

**Важно:** не «подавай 100 откликов». Match связывает накопленный профиль с конкретной возможностью.

## Модуль 11. Candidate Retention Loop

1. Уведомление о релевантной возможности.
2. Объяснение, почему вакансия считается релевантной.
3. Усилить только те компетенции, которые важны для новой возможности.
4. Каждое новое подтверждение увеличивает полезность профиля для будущих возможностей.

Превращает профиль из одноразовой анкеты в накопительный актив (retention / compounding value — критическая гипотеза MVP).

## Модуль 12. Recruiter Profile / Candidate View

> Строить только после проверки кандидатского ядра.

1. Найти кандидатов под вакансию без чтения десятков резюме.
2. Видеть PROF кандидата и соответствие требованиям.
3. Видеть Trust Score вместе с объяснением, какие Evidence его сформировали.
4. Видеть не только итоговый Score, но и области, требующие дополнительной проверки.
5. Сравнивать кандидатов по одинаковой структуре данных.

## Модуль 13. Progressive Reveal

1. Сначала минимально необходимая информация — первичный отбор по профессиональной релевантности.
2. Дополнительные сведения раскрываются на следующем этапе интереса.
3. Кандидат контролирует, какие данные доступны рекрутеру на каждом этапе.

Важно для Privacy/NDA respect и снижения bias.

## Модуль 14. Recruiter Feedback & Calibration

1. Отметить, был ли кандидат действительно релевантен.
2. Указать, какие части профиля были полезны или вводили в заблуждение.
3. Как оператор — использовать обратную связь для калибровки PROF и Trust.
4. Как оператор — проводить выборочный ручной аудит результатов.

## Модуль 15. Recruiter Plugin

1. Вставить или выделить текст вакансии либо резюме и получить структурированный анализ.
2. Увидеть ключевые требования вакансии и нужные для проверки Evidence.
3. Отправить кандидату приглашение на верификацию профиля.
4. Использовать результат в существующем workflow.

**Плагин не скрейпит страницу автоматически** — MVP предполагает ручное выделение текста.

## Модуль 16. Vacancy Aggregation / Reverse Matching [V2]

> Не в первый MVP, но заложить архитектурно.

1. Вакансии из нескольких источников в одном месте.
2. Автоматическое сопоставление найденных вакансий с PROF.
3. Только релевантные вакансии.
4. Рекрутер получает подходящих кандидатов с верифицированным профилем.
5. Агрегированный рынок вакансий как источник candidate acquisition и reverse matching.

## Четыре этапа

| Этап | Модули | Поток | Главный вопрос |
|---|---|---|---|
| 1. Candidate Core | 1–6 | Profile → Evidence → PROF → Contextual Probe → NDA → Trust | Готов ли кандидат создавать и накапливать верифицированный профиль? |
| 2. Compounding | 7–11 | XAI → модерация → накопление → export → Match → retention | Становится ли профиль ценнее со временем и возвращается ли кандидат? |
| 3. Recruiter Value | 12–15 | Recruiter View → Progressive Reveal → Feedback → Plugin | Меняет ли Trust/PROF решение рекрутера? |
| 4. Marketplace / Growth [V2] | 16 | Aggregation → Match → Reverse Matching | Можно ли превратить репутацию в двухсторонний рынок? |

Порядок проверки гипотез: **1. кандидат готов к верификации → 2. Trust отражает достоверность → 3. Trust нужен рекрутеру → 4. рекрутер готов платить.**

## Принципиальное замечание по разработке

Разработку **не начинать с Модуля 12 и дальше.** Самый дешёвый способ проверить главную гипотезу — кандидатский эксперимент **без единого рекрутера**:

> профиль → One-Click Enrichment → PROF → белые пятна → Contextual Probe → Trust → экспорт

Первая версия — **модули 1 → 9**. Модули **10–15 подключать только после первых данных**, иначе получится recruiter-side продукт до доказательства накопительной ценности для кандидата.
